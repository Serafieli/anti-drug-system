# AntiDrugSystem

AntiDrugSystem — прототип системы для автоматизированного поиска и анализа открытых веб-источников. Изначальная идея проекта — выявление сайтов, потенциально связанных с распространением запрещённых веществ. В представленной демонстрационной версии поисковая тематика изменена на продукты питания и рестораны: приложение собирает общедоступные контакты, сохраняет результаты в SQLite и позволяет просматривать и экспортировать данные.

**Стек:** Node.js · JavaScript · SQLite (`node:sqlite`) · HTML · CSS · Tailwind CSS · Lucide

## Возможности

- **Автопоиск по каталогу.** 100 готовых запросов о ресторанах, продуктах и услугах питания, сгруппированных в пять категорий. Запросы можно включать, отключать и дополнять.
- **Два поисковых источника.** Основной поиск через DuckDuckGo; Bing используется как резервный источник, когда результатов недостаточно.
- **Сбор открытых контактов.** Извлечение телефонов, email и ссылок на Telegram, WhatsApp, ВКонтакте и Instagram со страниц организаций.
- **Углублённый анализ.** Если на основной странице не найдены телефон и почта, система может дополнительно проверить страницы контактов и информации о компании.
- **Управление очередью.** Настройка глубины поиска и задержек между сайтами; запуск, пауза, продолжение и остановка обработки.
- **Хранение и поиск.** SQLite-база с историей найденных сайтов, фильтрацией по контактам, поиском по тексту, просмотром записей и статистикой.
- **Экспорт результатов.** Форматированный Excel (`.xlsx`), CSV и JSON. Доступно копирование телефонных номеров и просмотр журнала обработки.

> Проект разработан в рамках **AntiDrug Hackathon**, организованного **Aqmola Hub**. Чтобы продемонстрировать технологию без поиска предложений запрещённых веществ и связанных с ними ресурсов, стандартный каталог заменён на нейтральные запросы о продуктах, кафе и ресторанах. Ручной поиск технически принимает произвольный запрос или URL.

## Как это работает

```text
Каталог запросов о ресторанах / ручной поиск
                      |
                      v
             DuckDuckGo / Bing
                      |
                      v
               Список сайтов
                      |
                      v
         Загрузка и анализ HTML-страниц
                      |
                      v
      Контакты, описание, ссылки на соцсети
                      |
                      v
                SQLite-база
                      |
             +--------+--------+
             |                 |
             v                 v
       Веб-интерфейс       XLSX / CSV / JSON
```

При включённом углублённом анализе парсер проверяет подходящие внутренние страницы сайта, если на первой странице не нашлись основные контакты. Повторно обнаруженный URL обновляется в базе, а не обязательно добавляется отдельной строкой.

## Быстрый старт

Для работы потребуется **Node.js 24+** и доступ к интернету. Сервер использует встроенные модули Node.js — устанавливать npm-пакеты не нужно.

### 1. Подготовьте проект

Распакуйте архив в отдельную папку и откройте в ней PowerShell или терминал. Убедитесь, что Node.js установлен:

```powershell
node --version
```

Если команда не распознаётся, установите актуальную LTS-версию Node.js с [официального сайта](https://nodejs.org/).

### 2. Запустите сервер

```powershell
node server.js
```

После запуска интерфейс доступен по адресу:

**http://localhost:3000**

По умолчанию используется порт `3000`. Приложение создаёт структуру базы данных и добавляет 100 начальных поисковых фраз, если каталог пуст.

> Файлы `start.bat` и `start.ps1` из исходного архива используют абсолютный путь к Node.js на компьютере разработчика. На другом компьютере надёжнее запускать приложение командой `node server.js`.

### 3. Выполните поиск

1. Откройте вкладку **«Каталог 100 слов про еду»** и проверьте активные запросы.
2. Перейдите в **«Автопоиск и Очередь»**.
3. Выберите глубину: `5`, `8`, `12` или `20` сайтов на запрос.
4. Установите задержку между сайтами: `1,5`, `2,5` или `4` секунды.
5. При необходимости включите проверку страниц контактов и запустите очередь.
6. Результаты откройте во вкладке **«Собранные контакты & Данные»**.

Для отдельного запроса или проверки конкретного сайта используйте вкладку **«Быстрый поиск / Парсинг URL»**.

## Работа с данными

Каждая сохранённая запись содержит:

| Поле | Содержание |
| --- | --- |
| Запрос | Ключевая фраза, по которой найден сайт |
| URL и домен | Адрес источника |
| Название и описание | Заголовок страницы, мета-описание или фрагмент текста |
| Телефоны и email | Контактные данные, опубликованные на странице |
| Социальные сети | Найденные ссылки на мессенджеры и профили |
| Дата сбора | Время сохранения или обновления записи |

В таблице предусмотрены поиск, фильтры по типу контактов, просмотр подробностей и удаление записей.

### Экспорт

| Формат | Особенности |
| --- | --- |
| `.xlsx` | Оформленная таблица с шириной колонок, переносом текста, фильтрами и закреплённой шапкой |
| `.csv` | Разделитель `;`, кодировка UTF-8 с BOM для совместимости с Excel |
| `.json` | Структурированные записи для дальнейшей обработки |

## API

Сервер предоставляет локальные HTTP-маршруты, которые использует веб-интерфейс.

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/stats` | Сводная статистика и статус очереди |
| `GET /api/records` | Список записей с поиском, фильтрами и пагинацией |
| `GET /api/keywords` | Каталог поисковых фраз |
| `POST /api/keywords` | Добавление поисковой фразы |
| `POST /api/queue/start` | Запуск массового поиска |
| `POST /api/queue/pause` | Приостановка очереди |
| `POST /api/queue/resume` | Продолжение очереди |
| `POST /api/queue/stop` | Остановка очереди |
| `POST /api/search/single` | Быстрый поиск или обработка URL |
| `GET /api/logs` | Последние сообщения журнала |
| `GET /api/export/xlsx` | Скачать Excel |
| `GET /api/export/csv` | Скачать CSV |
| `GET /api/export/json` | Скачать JSON |

Пример тела запроса для `POST /api/search/single`:

```json
{
  "query": "пекарня Кокшетау",
  "depth": 5
}
```

Если `query` начинается с `http://` или `https://`, сервер анализирует указанный URL без предварительного поиска в поисковиках.

## Структура проекта

```text
AntiDrugSystem/
├── server.js             # HTTP-сервер, API и раздача интерфейса
├── scraper.js            # Поисковые запросы, анализ HTML и извлечение контактов
├── db.js                 # SQLite, каталог запросов, записи и статистика
├── excelExporter.js      # Формирование XLSX без внешней библиотеки
├── public/
│   ├── index.html        # Основная страница веб-интерфейса
│   ├── styles.css        # Стили и оформление
│   └── app.js            # Работа с API, таблицами и очередью
├── start.bat             # Скрипт запуска Windows
├── start.ps1             # Скрипт запуска PowerShell
├── antidrugsystem.db     # Локальная база данных SQLite
└── README.md
```

При работе SQLite также может создавать `antidrugsystem.db-wal` и `antidrugsystem.db-shm` — служебные файлы режима WAL.

## Важно знать

- **Поиск зависит от внешних сайтов.** Поисковики могут менять разметку выдачи или ограничивать автоматические запросы. У некоторых сайтов контакты отсутствуют или скрыты от обычной HTML-загрузки.
- **Нет гарантии полноты данных.** Программа анализирует открытые страницы и не подтверждает актуальность найденных телефонов и адресов почты.
- **Ручной поиск универсален.** Несмотря на ресторанную направленность встроенного каталога, сервер принимает произвольный текст или URL. Используйте его только для законных задач и открытых источников.
- **Интерфейс частично зависит от CDN.** Tailwind CSS, Lucide и веб-шрифты загружаются из интернета.
- **Нет авторизации.** Текущая версия рассчитана на локальную демонстрацию. API позволяет управлять очередью и удалять данные; публиковать сервер в открытый интернет без дополнительной защиты нельзя.
- **Учитывайте правила сайтов.** Автоматический сбор необходимо выполнять с соблюдением условий использования ресурсов и требований к персональным данным.
- **Не публикуйте рабочую базу.** Перед загрузкой проекта в публичный GitHub исключите `*.db`, `*.db-wal` и `*.db-shm`, если в них содержатся собранные контакты или другая рабочая информация.

## Разработка

Проект создан в рамках **AntiDrug Hackathon by Aqmola Hub**. Его исходная концепция направлена на обнаружение интернет-ресурсов, потенциально связанных с незаконным распространением запрещённых веществ. Для соблюдения правовых и этических ограничений демонстрационная сборка перенастроена на поиск продуктов, ресторанов, кафе и служб доставки еды; сбор сведений о запрещённых веществах не входит в демонстрационный сценарий.

Серверные маршруты находятся в `server.js`, механизм поиска и извлечения данных — в `scraper.js`, работа с SQLite — в `db.js`. Интерфейс реализован в папке `public/`.
